# Requirements & Progress

## Requirements Overview

Prompt 3 Part A - Platform Core Completion
Implementing 9 major platform core features using existing Prompt 1 & 2 infrastructure:
1. Authentication UI (Sign In, Registration, Password Reset)
2. User Profile (View/Edit personal info, preferences)
3. Role-Based Navigation (Platform Owner, Academy Owner, Staff, Instructor, Student, Guest)
4. Platform Owner Dashboard (Platform-wide overview, metrics, activity)
5. Platform Settings (Global configuration, preferences)
6. Notifications UI (Notification center, read/unread state)
7. Billing UI (Plans, subscriptions, invoices - UI only, no real integration)
8. Analytics UI (Platform-level metrics, charts, KPIs)
9. Search Experience (Search input, results, keyboard interaction)

## User Stories

US-1: As an unauthenticated user, I can sign in with email/password
US-2: As an authenticated user, I can view and edit my profile information
US-3: As a Platform Owner, I see platform-wide dashboard with key metrics
US-4: As a user, I see navigation appropriate to my role and permissions
US-5: As a Platform Owner, I can configure platform settings
US-6: As an authenticated user, I can view and manage my notifications
US-7: As a Platform Owner, I can view billing information and subscription status
US-8: As a Platform Owner, I can view platform analytics and reports
US-9: As an authenticated user, I can search across the platform

Prompt 3 Part B - Academy Management
Academy Dashboard, Creation, Profile, Settings, Branding, Members, Onboarding, Switching, permission-aware navigation.

Prompt 3 Part C - Course Management (final part of Prompt 3)
Course CRUD, categories, pricing/visibility representation, the Course Builder (sections + lessons + ordering), the draft/publish workflow, and Course-level settings/authorization/navigation — built on top of the completed Platform Core and Academy Management, with the backend kept fully abstract.

US-10: As an academy owner, I can view, search and filter my academy's courses
US-11: As an academy owner, I can create a course with its basic information, category, pricing and visibility
US-12: As an academy owner, I can edit an existing course's information
US-13: As an academy owner, I can organize a course's curriculum into sections and lessons, and reorder them
US-14: As an academy owner, I can publish a course when it's ready and unpublish it later
US-15: As an academy owner, I cannot access another academy's courses, and a user without course permissions cannot access Course Management routes

Prompt 4 - Student Learning & Assessment
The student-facing learning experience on top of the completed Academy + Course Management foundation: discovery, enrollment, curriculum navigation, lesson consumption, progress, quizzes, assignments, course completion and certificate-eligibility state. Backend remains abstract.

US-16: As a student, I can discover published courses across every academy
US-17: As a student, I can view a course's details and enroll in it through the abstract service contract
US-18: As a student, I can navigate a course's curriculum, consume lessons and mark them complete
US-19: As a student, I can resume a course where I left off
US-20: As a student, I can take a quiz, answer its questions, submit an attempt and see my result
US-21: As a student, I can view an assignment, submit a response (with an optional attachment) and see my submission state
US-22: As a student, I can see my course completion state and certificate eligibility, without any real certificate being generated
US-23: As a student, I can never see another student's progress, attempts or submissions, and a user without the right permission cannot access a protected learning route

Prompt 5 - Instructor / Teaching Operations + Communication & Knowledge Modules
The instructor-facing teaching experience on top of the completed Academy + Course + Student Learning foundation (Dashboard, My Courses, Course Overview, Student Roster, Student Progress, Assessment Management, Assignment Grading, Quiz Results), plus three new cross-role modules: Announcements, Knowledge Blog, and Course Forum. Backend remains abstract throughout.

US-24: As an instructor, I can see a dashboard summarizing the courses I teach, my students, and my pending grading work
US-25: As an instructor, I can see the list of courses I am authorized to teach, and open one to see its overview, roster and assessments
US-26: As an instructor, I can see the students enrolled in a course I teach and their individual progress, quiz attempts and submissions — read-only
US-27: As an instructor, I can grade an assignment submission with a score and feedback, but only if I hold the grading permission
US-28: As an instructor, I can see every quiz's results across all students in a course I teach, without ever seeing another course's data
US-29: As an instructor, I can author, publish and archive announcements scoped to a course I teach
US-30: As any authenticated user, I can see the announcements feed relevant to me (platform, my academies, my courses)
US-31: As any authenticated user with the right permission, I can read and author Knowledge Blog posts, distinct from the platform's existing static marketing blog
US-32: As a student or instructor, I can discuss a course in its forum — post threads, reply, and (if authorized) pin/lock threads for moderation
US-33: An instructor can never reach another instructor's course data, another course's forum/announcements, or gain Academy Owner-level permissions through any Instructor page or service

Prompt 6 - Atlas SaaS Foundation, Tenancy, Subscriptions, Plans, Entitlements, Usage & Platform Admin
The SaaS foundation that turns Atlas from an education application into a real multi-tenant SaaS platform, on top of the completed Platform Core + Academy + Course + Student Learning + Instructor/Community foundation. Organization is the Tenant boundary. Backend remains fully abstract; no payment provider exists.

US-34: As a Tenant Owner, I can see my organization's subscription — plan, lifecycle status, and trial/grace countdown where applicable
US-35: As a Tenant Owner, I can see my organization's usage against its plan's resource limits, including general and video storage tracked separately
US-36: As a Tenant Owner, I can see which Add-ons are active on my subscription, and which further catalog Add-ons exist
US-37: As a Tenant Owner, when a limit is reached or a feature is unavailable, I can see whether an upgrade or a compatible Add-on would resolve it and compare plans — without the frontend ever claiming a plan change or payment happened
US-38: As the Atlas Platform Owner, I can configure whether new organizations receive a free trial and its duration (including disabling it entirely), without a hardcoded 7-day business rule anywhere in the codebase
US-39: As any user, my organization's subscription/usage/add-ons can never leak to a different organization after switching, and no Tenant page or permission can reach Platform Owner-only SaaS administration

Prompt 7 - Atlas Enterprise Billing & Payment Platform
The complete payment engine on top of Prompt 6's SaaS foundation: a provider-agnostic Checkout/Payment domain, Manual Bank/Wallet Transfer as the two currently-available payment methods behind a real `ManualTransferProvider`, and a gateway-ready architecture (provider abstraction, payment intents, capabilities, redirect/return handling, webhook contract) that connects zero real payment providers. No real gateway, no gateway SDK, no card-data collection, no fake webhooks — every "gateway-ready" piece is a real, typed, callable contract with no concrete implementation behind it yet.

US-40: As a Tenant Owner, I can select a plan or add-on and check out — reviewing a frozen commercial snapshot before choosing a payment method
US-41: As a Tenant Owner, I can pay by bank transfer or wallet transfer, submitting proof of payment for review, and see my payment move through created → pending review → approved/rejected → succeeded/failed
US-42: As a Tenant Owner, I can see my full payment history and every payment's detail — provider-agnostic, whether manual or (in the future) gateway-based
US-43: As a Tenant Owner, I can see my organization's invoices
US-44: As the Atlas Platform Owner (or a delegated billing reviewer), I can see manual payments awaiting review across every organization, and approve or reject them with notes
US-45: As a reviewer, I can never approve or reject my own organization's payment
US-46: As any user, a payment's success is only ever shown once the backend authoritatively confirms it — never from proof upload, a button click, or a gateway redirect's query string
US-47: As any user, my organization's Checkout/Payment/Invoice data can never leak to a different organization after switching, and the payment engine is architecturally ready for a real gateway to be added later as an adapter, not a rewrite

Prompt 8 - Atlas Provisioning + Academy Lifecycle
The orchestration domain that turns an eligible request into a ready Academy: Tenant → Academy → Theme → Branding → Subdomain → Domain → Provisioning → Ready, on top of Prompt 6's entitlements and Prompt 7's commerce. A real, idempotent, resumable state machine with step-level detail — no real DNS/SSL/infrastructure, no Theme Engine, no fake progress. Every status shown is backend-authoritative; nothing here simulates provisioning.

US-48: As a Tenant Owner, I can start provisioning a new Academy — choosing a name and an Atlas address (subdomain) with live availability checking — as long as my plan's Academy limit isn't already reached
US-49: As a Tenant Owner, I can watch my Academy's provisioning progress step by step, leave the page and come back later, and see the same real state restored
US-50: As a Tenant Owner, if provisioning fails, I can see a safe, professional explanation and retry — without any completed step (Tenant, Academy, Theme, Branding) being recreated
US-51: As a Tenant Owner, I can see every provisioning request I've made, and once one is ready, go straight to my new Academy's dashboard
US-52: As the Atlas Platform Owner (or a delegated operator), I can see every Academy currently being provisioned across every organization, and retry or cancel a request
US-53: As any user, one organization's provisioning requests can never leak into another's, plan-limit enforcement never depends on a hardcoded plan name, and re-submitting the same request never conceptually creates duplicate resources

Prompt 9 - Atlas Theme Engine + Website Experience Platform
The multi-tenant Theme Engine and Page Composer for an Academy's public website, on top of Prompt 3B/3C's Academy/Course domains — five genuinely distinct built-in themes driven by a bounded design-token + structural-variant system, an 11-type Section Registry, a draft/publish website configuration model, and one shared renderer used identically by the Theme gallery, the live editor preview, and the in-dashboard Preview surface. No real public multi-tenant routing, no arbitrary HTML/CSS/JS execution, no Course domain duplication.

US-54: As an Academy Owner, I can browse five distinct professional themes, see a live preview of each using my own content and branding, and switch between them without losing any page content or configuration
US-55: As an Academy Owner, I can set my brand colors and a dark-background logo, with an accessibility contrast warning, while my primary logo/favicon continue to be managed on the existing Academy Branding page
US-56: As an Academy Owner, I can show/hide core pages (Home, About, Courses, FAQs, Contact) and create custom pages built from registered sections — never arbitrary HTML
US-57: As an Academy Owner, I can add, remove, hide, reorder, duplicate and configure sections on any page, with per-breakpoint (desktop/tablet/mobile) visibility, through an accessible, keyboard-operable Page Composer
US-58: As an Academy Owner, I can manage my website's navigation, header call-to-action and footer, and configure global and per-page SEO
US-59: As an Academy Owner, my website has an explicit draft/published state; I can preview my draft at any time and the public configuration only changes when I explicitly publish and the backend confirms it
US-60: As any user, a Course Details page always reflects the real, live Course Management data — never a duplicated projection — and one Academy's website configuration can never leak into another's

Prompt 10 - Atlas CMS + SEO Platform
Structured Website Content Management + Academy/Tenant SEO, on top of Prompt 9's Theme Engine and Page Composer — a reusable FAQ/Testimonial content library (independently EN/AR localized, draft/published/archived), referenced by id from any page's FAQ/Testimonials section, plus an independent SEO domain (global + page-level, a deterministic Override → Global → Fallback resolution hierarchy, structured-data and sitemap contracts). CMS and SEO are two separate architectural domains implemented in one prompt. No public website runtime, no DNS/SSL/CDN, no Course/Instructor domain duplication, no arbitrary HTML/JS in any content model.

US-61: As an Academy Owner, I can build a reusable library of FAQ entries and testimonials, each independently written in English and Arabic, and reference them from any page's FAQ or Testimonials section instead of retyping the same content on every page
US-62: As an Academy Owner, a FAQ or testimonial entry has its own draft/published/archived lifecycle; only published, visible entries I've referenced ever appear on my website, and archiving is never a silent hard delete
US-63: As an Academy Owner, I can configure my website's global SEO defaults (site title, meta title/description, social share image, indexing, sitemap inclusion) and, independently, override any of those per page
US-64: As an Academy Owner, when I leave a page's SEO fields blank, I can see exactly what my website will use instead — my own page value, then the website's global default, then a system fallback — never an unexplained empty result
US-65: As an Academy Owner, I can preview the structured data (JSON-LD) and sitemap entries a future public website would publish, entirely derived from my real Academy/Course/page data, before any of it is actually served publicly
US-66: As an Academy Owner, my Course Details and Blog pages' SEO is always derived from the real, live Course/Blog record — never a duplicated projection — and changing my website's theme never changes a single SEO value
US-67: As any user, one Academy's FAQ/testimonial library and SEO configuration can never leak into another's, and publishing an entry is always a deliberate, permission-gated action distinct from merely editing it
